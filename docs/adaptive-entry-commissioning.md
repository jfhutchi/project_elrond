# Adaptive PAPER entry commissioning

The default `experiment_launch` remains SHADOW-only. The separate
`experiment_entry` launcher supplies retained PAPER services before the unchanged
coordinator records decisions. It never writes an approval, activation, deployment
or promotion. A configuration flag cannot supply these authorities.

## Before transferring entry ownership

1. Establish applicable repository rules, review the consolidated dependency
   tree, and pin the exact tested release commit. Do not bypass unknown rules.
2. Preserve the existing release's hashed core bytes. Verify `pooled_code_hash`
   against the registered manifest; a Git-identical CRLF/LF checkout can have a
   different raw-byte hash. Abort on mismatch rather than re-registering evidence
   or consuming another fit.
3. Use a separately pinned `EntryLaunchConfig` and pinned coordinator configuration.
   Initial entry transfer requires `research_sources=null`, preventing additional
   fits from being enabled implicitly. Retain the registered six-call budget,
   grandfathered holdings baseline, exact binding, existing tighter limits,
   measured risk gates, kill switch, independent protection and deadline ownership.
4. Run the entry CLI with `--check`, verifying both configuration hashes, manifest
   and clean release. This is source preflight, not runtime commissioning.
5. Back up nonsecret configuration, task XML and a consistent experiment-store
   snapshot; verify snapshot integrity and restore equality in isolation. Do not
   copy credentials or plan to restore an operational database over later evidence.

## Exact activation and initial market window

An operator must approve the exact model, activation package and binding. Durable
activation additionally requires a genuine current cohort and retained operational
deployment/PAPER_OBSERVATION prerequisites. Never fabricate a cohort to activate
overnight. Historical validation loss is exploratory, not prospective profitability.

The existing entry predecessor is named `Elrond DIA Learner`. A nonexistent older
alias cannot satisfy the ownership check. The new SHADOW predecessor must also be
registered and explicitly stopped before transfer.

After activation, use a *later* fresh cohort: the coordinator requires the
activation timestamp to precede each decision. The entry preparer computes service
inputs in memory; the coordinator journals exactly one immutable decision for each
model/feature pair. It does not append a second activated version of a SHADOW
forecast. A veto or no-cost-edge result is an honest no-trade outcome.

Before starting the new task, disable and verify both predecessor entry/SHADOW
tasks are stopped. The launcher checks their fixed names and disabled states on
every preparation. Keep the existing protection, independent deadlines, observer,
daily close capture and console running. Register only the limited existing task
principal and supplied Windows job wrapper; no elevation or new credentials.

## Recovery and rollback

While exact activation remains valid, an unresolved experiment outbox blocks new
entries. A recovery-only wake can provide archived, guarded service inputs without
a fresh cohort and without an entry context. The unchanged dispatcher looks up
already claimed sends and records durable acknowledgements; it cannot resend a
new entry. Unclaimed or unresolvable records require explicit reconciliation.
After activation has ended, this launcher does not reconstruct execution authority;
independent position protection continues and remaining outbox reconciliation
must use the supported recovery procedure.

Rollback stops only the new entry task and returns the experiment to observation.
Retain all later journals, fit charges, acknowledgements and lots. Resume a previous
entry task only after verifying its binding remains valid and that no unresolved
new owned lot/outbox would create competing authority. Keep independent exit and
deadline protection until owned positions are flat. Do not liquidate grandfathered
positions, reset the account, or rewind databases as a rollback shortcut.

Commissioning acceptance requires natural scheduled receipts, exact activated
decision identity, retained risk and ownership gates, and actual broker/account
reconciliation. Synthetic graph tests are not actual PAPER fills. Full prospective
acceptance still needs a genuine eligible fill, protected exit, reconciled outcome
and fresh evaluation; never manufacture an order to complete the checklist.

The external alert route remains pinned to its separately approved catalog.
Added source-only codes are not transmitted by this commissioning procedure.
