# Bounded news-context and interpreter-feedback slice

November 6, 2026. This records local implementation and synthetic regression evidence, not a deployed news strategy, authentic interpreter fit, provider-rights determination or profitability result.

## Implemented interfaces

[external_context.py](../../src/quantbot/paper_core/external_context.py) contains pure immutable contracts and functions; it creates no database, worker or network client.

- `SourcePermissions` separates access, metadata retention, text retention, processing and training. Each defaults to UNKNOWN and verified claims require evidence references. These are inputs from an independently verified rights review, not permissions inferred by code from HTTP success.
- `document_from_research(payload, document_id=..., permissions=..., asset_refs=...)` verifies the existing journal kind/digest and preserves publication, revision and original first-observed time. Asset references must come from a verified mapping. Unknown text-retention rights produce a metadata-only document with no title/summary text. Unknown metadata-retention or access rights refuse adaptation.
- `build_context_snapshot(documents, symbol=..., at=..., coverage=..., used_document_ids=...)` selects the latest available story vintage, excludes late/stale/invalidated items, and distinguishes observed, eligible and actually-used IDs. An omitted used list means observed-only context. X and Reddit are explicitly unavailable in this pipeline.
- `interpret_document` is version `news-lexical-negation-v1`: bounded headline/summary token rules, clause-local negation and event tags. Multiple tagged entities are ambiguous. Processing permission is required even for token extraction. Direction is an unvalidated heuristic with a proposed 30-minute horizon; expected return and numerical confidence remain unknown. No LLM is called, and text is never executed as instructions.
- Snapshot features describe only actually-used readings: count, positive/negative counts, mean polarity, disagreement and missing-provider coverage. Serialization validation checks source/timestamp membership and feature consistency.

[context_feedback.py](../../src/quantbot/learner/context_feedback.py) separates reading labels from subsequent market economics.

- `ReadingReview` requires explicit human-review or source-correction authority with hashed independent evidence available before review. Outcome-only and inconclusive reviews never produce reading labels. Fact, entity, predictive and execution reviews remain separate categories; this bounded fit learns sentiment polarity only. A confirmed positive reading remains positive when the associated trade loses money.
- `build_examples(snapshots, documents, reviews, as_of=..., invalidations=..., training_permissions=...)` preserves original readings, joins available independent labels, excludes conflicts and duplicate source clusters, and records document/review/permission lineage. A later verified training grant can be supplied separately without rewriting original availability or processing provenance.
- `fit_interpreter_candidate(examples, split_at=..., as_of=...)` performs an actual fixed ridge fit using existing estimator utilities. Training labels must have been available before the split. The chronological holdout supplies neither scaling nor coefficients and is compared with the original heuristic. Eight training sources, four heldout sources and at least two dates per side are mechanical minimums, not statistical-power or promotion guarantees. Inputs are bounded at 2,000 rows; alpha is fixed at 1 and seed at 0. No parameter search or activation occurs.
- `candidate_polarity` applies the fitted candidate to a later reading only, with candidate identity retained by the caller. `candidate_usable` rejects artifacts whose lineage has been invalidated. Candidates carry `grants_activation=False`; existing trial, walk-forward, promotion and rollback gates still apply.
- `compare_context_to_price_only` fits price-only and price-plus-context ridge arms against the same caller-supplied modeled-net or actual-net labels and chronological holdout. It verifies source availability, original readings, training rights and disjoint source clusters. These returns never become reading-correction labels. Cost evidence remains explicit; forecast MSE is not profitability.

Reviews and interpreter candidates include `experiment_id` and `recorded_at`, so the existing registered `ExperimentStore` appends them without another persistence framework. Repeated predeclared walk-forward folds and activation remain separate gates.

## Durable integration added November 6

[paper_core/context_integration.py](../../src/quantbot/paper_core/context_integration.py) reads bounded, indexed existing research vintages and persists a `ContextCapture` in the existing discovery receipts. `capture_research_context(state, symbol=..., at=..., permissions=..., maximum_documents=100)` returns an observed-only snapshot or `None` when no permitted bindings exist. Empty context writes nothing. Unchanged source, permission and interpreter state reuses the prior immutable snapshot and original capture timestamp. The snapshot is stored once, without duplicating source article text. Metadata indexes connect its stable ID to its capture receipt.

`load_source_permissions(state)` reads a bounded validated list from existing metadata key `context:source-permissions`; it does not infer entitlement or read environment secrets. `permission_coverage(permissions, at=...)` reports unavailable/unknown coverage even when no snapshot is stored. No production permission records were added. SEC aggregates retain `published_at=None` and their real first-seen time, with no narrative/sentiment claim. Their existing symbol index uses aggregate `observed_at` as the search timestamp; this does not become a publication timestamp.

[learner/context_integration.py](../../src/quantbot/learner/context_integration.py) exposes callable learner operations rather than another worker:

- `journal_context_snapshot` links a retained capture to a registered experiment, idempotently.
- Retain real `ReadingReview` records through existing `ExperimentStore.append`; optional `ContextPermissionRecord` grants carry independent permission provenance and recording times.
- `evaluate_retained_context(store, research, experiment_id=..., split_at=..., as_of=..., guard=..., charger=...)` loads retained snapshots/reviews/permissions/invalidation records, builds eligible examples, charges an admitted fit, and persists both the fitted interpreter candidate and chronological heldout evaluation. Missing real reviews or admission produces a durable refusal. Admission is required before source training payloads are opened. The existing event reader now accepts an optional hard bound and fails instead of silently truncating evidence.
- `journal_invalidation` appends a tombstone, and `load_retained_candidate` checks current retained invalidations before returning a candidate. This does not activate it.

The existing price learner's `CanonicalTrialCharger` accepts a fixed ten-price-feature `FitRequest`. Context fitting now has its own [context_admission.py](../../src/quantbot/learner/context_admission.py) adapter, using the existing `HypothesisRegistry`, declaration guard and permanent intraday accounting without coercing context examples into that price request format or creating another database.

`register_context_plan(store, plan, now=...)` freezes one `ContextEvaluationPlan` against the registered experiment manifest before training begins. It declares source lookback, training start, split, final evidence cutoff, fixed interpreter version and fixed ridge estimator. Altering its window is refused. `run_registered_context_evaluation(store, research, experiment_id=..., registry_path=..., declaration_path=..., now=...)` is the operational learner API: both existing absolute registry/declaration paths are required, protected/forward-paper/declared holdout ranges are refused, and evidence is evaluated only at the predeclared cutoff. Later corrections do not retune that holdout. The actual evaluation/candidate creation time remains separate from the earlier evidence cutoff.

The canonical charge commits before fitting, survives local-store loss, prevents a second context fold inspection, and shares the registered experiment's existing six-call budget with adaptive price fits in both directions. Context attempts retain the existing conservative `us-equities-daily` accounting burden; this is an accounting namespace, not a claim that news or crypto observations are daily equity prices. Evaluations explicitly name their plan, and candidates retain its ID in lineage. Repeated unchanged insufficient-evidence checks return the prior receipt. Later invalidation or revoked permission blocks reuse. This one chronological reading-validation fold is not an authorization to consume an independently protected registry holdout, a multi-fold walk-forward qualification, or an activation gate pass.

Authentic permitted independent reviews, sufficient prospective examples, additional predeclared walk-forward qualification and activation remain outstanding. No operational command manufactures missing labels and no context model is active. The user subsequently confirmed Alpaca news is included at no extra charge; rollout/settings changes belong to the coordinator, and that access confirmation does not itself establish text retention, processing or training rights.

Observation/decision `context_snapshot_id` linkage is optional, preserves legacy identity when omitted and does not alter price features or decision gates. For downstream outcome comparisons, `DownstreamExample.decision_at` is the actual trade decision timestamp, separate from the reusable snapshot's original `context.at`; price availability, labels and train/holdout splits use the actual decision time. A reused old news snapshot cannot backdate a later trade into training.

## Deletion and rights changes

`SourceInvalidation` records deletion, redaction or rights revocation by a stable reference. Example construction excludes affected lineage, and existing candidates fail the usability check. Decision reference identities survive. Storage integration must separately purge prohibited source text and derived readable content, retain only permitted tombstone metadata, and enforce invalidation at every candidate use; these pure functions are not a file-deletion service. Passing an outdated invalidation set cannot establish current permission.
