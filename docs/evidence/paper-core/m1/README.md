## Authority and migration

Migration 0030 is additive from current 0029. Normal database opening continues to refuse migration. Only temporary fixtures were migrated; manual pauses and legacy rows are preserved, SQLite integrity and online backup/restore are checked, and v30 refuses destructive downgrade. Reused protection accepts only snapshots affirmatively linked to validated core certifications. Legacy snapshots lacking proof remain unproven. Same-run historical reconciliation was deliberately not grandfathered because the legacy runner/recovery path can compare newly ingested raw cash against itself. Raw protection snapshots are still retained and marked; repeated mismatches cannot advance certified state.

Certification derives cash, aggregate quantity, per-owned-lot basis and fill/order watermark from the immutable synthetic initial baseline plus canonical owned fills. It checks actual quantities/cash/basis, the baseline ID, watermark and generation. Refused proofs remain durable; the certification generation does not advance. Marks are preserved rather than replaced with a fabricated price. The existing legacy mark-timestamp issue is outside this narrow repair and remains M3 work.

One writer transaction records decision, canonical intent, protection plan and position-slot reservation. The independent guardian module acknowledges that handoff before synthetic POST; the fixture harness invokes that acknowledgement in process for entry, then verifies independent process exit after the fill. Canonical entry identity is based on binding and observation, with a unique SQLite entry-observation claim. The existing `ExecutionCoordinator` alone handles broker submission/lifecycle and final manual-pause checking. Its existing account gates remain enabled using explicit nonsecret synthetic placeholders. Drawdown, veto, clock/session and initial ownership evidence are fixture assumptions; they cannot authorize a real broker.

Rollback of this uncommissioned work is a source revert in the isolated branch. Retain evidence and temporary backup copies. Do not restore a pre-trade database over newer broker events. A deployed v30 store would require compatible readers/protection or forward repair, not destructive downgrade; no operational migration/deployment is claimed here.

## M1 rework after independent review

The initial independent review found a final-send lifetime gap; the broad run at `8ccdb39` found 11 regressions (4,336 passed, 47 skipped and one existing Starlette warning). Root owns those initial review/broad artifacts and acceptance status. [rework-red.txt](rework-red.txt) reproduces all 11 broad failures plus six failing final-send cases. [rework-green.txt](rework-green.txt) records **325 passed in 96.70 seconds**, including every affected module, M0/M1, final-send fault cases, and retained coordinator/deadline/storage/migration/protection checks. No second whole-project suite is claimed. Full CI-equivalent Ruff and both Linux/Windows source/helper type targets passed; `rework-ruff.txt` and `rework-mypy-*.txt` retain outputs.

The coordinator now accepts an optional synchronous final-send guard (default None for retained callers). Core entry authority is consumed after the final awaited acquisition. The guard reads durable decision/plan/latest matching guardian acknowledgement and samples the current injected synthetic clock after SQLite reads/lock acquisition. Decision, protection/session deadline and receipt expiry are exclusive: equality refuses. Rejected entry records `CORE_ENTRY_SEND_REFUSED`, the consuming IDs/current check time and proven pre-SUBMITTING provenance, then reaches ERROR without POST or global stop. A refusal recorded just before a crash latches against a clock-reversed retry. Unknown/submitting recovery bypasses this fresh-entry guard and stays reserved; protocol ERROR without definitive refusal also stays reserved. Existing exits bypass entry expiry checks.

A later fresh observation can reuse the single position slot only when the earlier ERROR has that precise definitive-unsent event and no broker order. The old observation/intent/refusal remain immutable and cannot replay. [rework-refusal-recovery.json](rework-refusal-recovery.json), read through SQLite `mode=ro` from the passing fixture, joins the 14:31 expiry refusal for the 14:00 observation to a new 14:31 observation's accepted fill. Only one new fake POST occurs. This is scoped synthetic recovery, not M3 clock-policy or operating-state commissioning.

The broad regression fixes preserve original assertions. Fixture initialization now certifies while preserving its default pause; only the explicit thin-loop entry fixture opts into entry enablement. Legacy ownership tests build an explicitly test-only proof from initial capture and canonical owned fills, assert quantity 1/basis $100/cash $899.90, then certify that fixture snapshot; production does not automatically adopt legacy snapshots. V30 follows prior additive migrations' `checkfirst=True` behavior for already-existing tables while retaining the mandatory post-upgrade zero-diff schema comparison. A malformed preexisting core table still causes migration refusal and preserves the v29 marker. Operational stores remain untouched.
