DEPLOYED COST REPORT: EXISTING CAPABILITY AND LIMITS

- Selects BROKER_PAPER closed trips by Eastern exit/source_end date.
- Checks gross against exact entry/exit fill quantities and prices.
- Validates provider document digests, account, PAPER endpoint and capture cutoff.
- Deduplicates activity IDs and rejects conflicting payloads.

HIGHEST-IMPACT VERIFIED FIXES, IN ORDER
1. Shared local-origin protection for all console POST routes.
   Active app.py only checks client loopback, URL hostname and exact Origin for
   /learner/alerts/{source}/{code}/acknowledge (363-373).
   Other POSTs at 498,514,543,568,716,742,764 do not make that check:
   /kill-switch/engage, /kill-switch/clear, /operations/reconcile,
   /operations/sync-data, /config/policy/preview, /config/policy/apply,
   /config/policy/rollback.
   read_form only parses forms; GET middleware does not protect these requests.
   Readiness/proposal checks restrict effects but are not CSRF protection.
   Reject missing/null/foreign origin, unapproved Host and remote peer BEFORE
   form processing, callback, DB writes or network I/O. Share one expected-origin
   policy rather than only copying checks to individual endpoints. Keep legitimate
   local stop/resume and same-origin acknowledgements operational. Loopback
   binding alone does not prevent a browser on a malicious origin issuing POST.
   This finding is verified in BOTH checkout and deployed release.

2. Bound cost-reader execution without truncating truth.
   Active reporting/paper_costs.py:252+ uses read-only/query_only transaction and
   sqlite timeout=2 (lock acquisition wait), but no progress handler/deadline.
   It fetches ALL core_round_trips (266), ALL core_external_owner_events (281),
   current provider pointers (289), each referenced document, and all session
   openings/time evidence (301+). It repeats for every state snapshot/page;
   some non-calendar page paths recompute performance/costs separately.
   The external-event table has only id,payload (core_runtime_schema.py), so
   WHERE json_extract(...) alone does NOT establish a bounded indexed read.
   Smallest safe repair: monotonic SQLite VM progress deadline, bounded cumulative
   rows/bytes and document parsing budget; abort as explicit unavailable on budget
   exhaustion and close the read transaction. Do not LIMIT and silently publish
   partial totals or lose late fee corrections. This bounds cost reads, not all
   legacy ConsoleState reads; old list_runs and grouped action scans remain.
   Then avoid duplicate per-request reads by passing one report to all components.
   A later cache/materialized projection needs capture/as-of labels and complete
   update/correction invalidation; never retain stale results as fresh.
   A full period-indexed accounting exporter is a separate larger change.

   Extend tests/unit/console/test_overview.py. Do not merge legacy health and core
