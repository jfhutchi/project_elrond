# Local CI implementation plan

**Goal:** Reproduce the CI command suite locally without hosted runner minutes or deployment access.

**Architecture:** A PowerShell entry point launches a standard-library Python orchestrator. Each
job receives an exported, committed, clean source snapshot with its own Git baseline. Linux uses
an ephemeral Docker container with pinned uv/Python base image, no network during checks, no host
mounts, no capabilities, and no Docker socket. Windows runs natively with an allowlisted environment
and temporary home/state. Both call one shared check script also used by the existing hosted matrix.

**Decision:** Direct Docker plus shared commands is smaller than act for this workflow, which has
no service containers or action-specific build logic. act cannot reproduce the Windows runner in a
Linux container. A registered self-hosted runner adds token lifecycle, scheduling and persistent
host exposure without improving command parity. No runner will be registered. A Linux container
reproduces Linux commands, not the entire ubuntu-latest image. Native Windows remains trusted-code
verification, not an OS sandbox for hostile tests.

**Scope:** Hosted triggers, permissions, job names and matrix stay unchanged. No operational code,
credentials, database, startup configuration, broker control, or kill switch is changed.

## Verification

Use temporary Git repositories and injected subprocess fakes only at the unavailable Docker
boundary. Exercise real Git export/cleanliness and real child processes for failure propagation.
Run `uv run --frozen pytest tests/unit/test_local_ci.py`, then full lint/types/tests. Exercise
`scripts/local-ci.ps1 -Platform windows` after committing the reviewed snapshot. Default/all must
return nonzero when Linux prerequisites are missing. Store logs under ignored `.local-ci/`.

## Outcome

Implementation and local review are delivered in draft PR #224. Detailed validation is in
`docs/local-ci.md`. Final default invocation at ae55026: 2695 passed, 7 skipped, two WSL failures;
lint and both type-check targets passed. The runner failed honestly and cleaned its temporary
Windows checkout. Twenty-one focused CI tests passed separately, including real bootstrap
configuration isolation and descendant termination. No runtime/trading source changed.

Linux image build/execution is **blocked by absent Docker** on the available host. This is not a
passing check. Windows/WSL service failures also appeared in the unmodified baseline and remain
unresolved. Issue #218 stays open; the draft is not represented as merge-ready. No installation,
hosted Actions dispatch, production-state change or merge was performed.
