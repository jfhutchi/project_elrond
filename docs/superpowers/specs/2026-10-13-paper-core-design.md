# A smaller PAPER trading and learning core

Status: **LOCAL IMPLEMENTATION APPROVED October 14, 2026; DEPLOYMENT NOT APPROVED.** Design dated October 13, 2026, America/New_York. The user's instruction to implement the reviewed changes authorizes isolated implementation and tests of the proposed contracts. Exact runtime, model-use and clock-contract commissioning remain subject to the concrete M6 rollout review.

The [source-backed audit](../../reviews/2026-10-13-paper-redesign/audit.md) is the basis for this design. The [single authoritative implementation plan](../plans/2026-10-13-paper-core.md) owns sequencing, review status and handoffs. The [test plan](../../reviews/2026-10-13-paper-redesign/test-plan.md) distinguishes existing reproducible failures, future acceptance tests, and broker-PAPER acceptance.

## Objective and boundaries

Regularly evaluate eligible opportunities from real market data, execute authorized PAPER trades, independently protect and close them, reconcile complete round trips, account for costs honestly, and use their outcomes in a bounded numerical learner. Improvement is a measured result; no daily improvement or trade-count guarantee is made. A few dozen completed trades/day is a capacity target, never a quota.

PAPER only. Preserve historical stores, fills, holdings, holdouts, trial charges and manual stops. No LIVE adapter/endpoint in the new core, no service purchases, new credentials, paid CI, security changes, resync, forced orders or silent stop clearance. Optional systems may be retired after their ownership/dependencies are verified. Existing protections remain active until a tested replacement acknowledges each owned lot.

**User refinement during review:** PAPER is currently a learning system; routine faults must not strand it behind a global kill-switch reset. The new core has no automatic global kill switch for clock/data/provider/acquisition interruptions. Use scoped recoverable entry waits and keep trustworthy outcome/learning progress running. A manual pause is an explicit operator choice. Genuine contradictions quarantine only the affected authority/evidence, extending to the account only when identity or ownership cannot be bounded safely.

## Alternatives and recommendation

| Approach | Benefit | Cost / risk | Decision |
|---|---|---|---|
| Patch each existing launcher and experiment path | Small initial diffs; least immediate handover | Preserves multiple outboxes/stores/identities, optional dependencies and incompatible health semantics; repeated integration work | Use only for urgent safety repair and narrow reusable fixes |
| Incrementally replace orchestration around retained primitives | Small integrated milestones; preserve broker recovery/ownership and historical evidence; replacement can run credential-free first | Requires explicit compatibility adapters, exit ownership handover and retirement gates | **Recommended** |
| Clean rewrite of broker, execution, protection, accounting and research | Attractive clean interface | Relearns uncertain-submission/partial-fill/restart failures; loses tested provenance assumptions; risky parallel ownership; more time before meaningful broker acceptance | Reject for this goal |

This is a new small runtime path inside the existing Python project, not a new platform. Keep SQLite, Decimal, existing HTTP adapter, causal feature mathematics, deterministic ridge, canonical protected-data/trial records and Windows process-tree supervision. Do not add Kafka, Redis, Kubernetes, another host, or a general workflow engine.

## Runtime: three required roles and an optional view

```text
Real market data -> Trader: observation -> decision -> entry gates -> durable intent
                                                           |
                                    shared execution/ownership primitives -> PAPER broker
                                                           |
Guardian: owned fills -> stop/deadline -> reduce-only intent -> reconciliation
                                                           |
Outcome/Learning worker: evidence -> round trip -> costs -> update / NO_CHANGE
                                                           |
                                        immutable model -> activation -> later decision

All roles -> one operational SQLite store <- read-only health / dashboard / exporter
```

1. **Trader** evaluates the selected symbol and its declared benchmark dependencies every five-minute bar boundary. It does no fitting or optional research. It reads a single active policy/model snapshot and makes one durable decision before proposing an intent. Empty eligible set means a recorded wait.
2. **Guardian** is a separate process, with independent startup/restart and protected scheduling priority. It recovers unknown submissions, imports fill/order activity, maintains certified ownership, performs reconciliation and controls all exits for new-core lots. Entry pause, model failure, missing unrelated-symbol data, or research failure cannot disable it. It does not create new exposure or adopt unexplained inventory.
3. **Outcome/Learning worker** processes durable evidence continuously, independent of market-open and entry status. Outcome progress has priority over bounded fitting. Fit runs in a time-limited subprocess without broker credentials or an operational database handle; it receives an immutable input export and writes only its result in scratch space. This is a restricted program interface, not a claim of a new OS sandbox. Learning failure never stops outcomes or the guardian.
4. **Optional dashboard/exporter** reads health and joined evidence. It is not execution authority. Existing alert transport may read this view; it is not a core dependency.

Three roles are justified by fault isolation: a trader crash must not defeat exits, and fitting must not delay either exits or outcome processing. No separate ingestion/news/model-server task is required for this path. The single-host OS/process lock plus SQLite transactional claims fence supported writers; broker account/client IDs defend duplicate intent recovery. This is not a claim of global distributed fencing. An unverified alternate entry writer blocks handover.

Proposed healthy scheduling defaults: guardian poll ≤15 s; completed-evidence worker poll ≤15 s, including closed sessions; entry once per fresh five-minute decision boundary; fit at most once per completed exchange session. These are testable service targets, not guarantees during provider outages. Guardian priority and lock latency are measured under load before commissioning. Do not impose a desired number of trades.

## Keep the economic identity separate from the release

- `release_id`: code SHA + locked dependency hash + supported schema + configuration hash + host/runtime identity. It changes with maintenance.
- `policy_id`: hash of strategy semantics—feature contract, entry rule, exit rule, cost basis and fixed risk envelope. Cosmetic/logging/launcher changes do not silently change it.
- `model_id`: hash of immutable coefficients, preprocessing and target contract; never a mutable filename such as `latest.pkl`.
- `experience_revision_id`: lot ID + ordered source evidence IDs + cost revision + resolver contract.
- `deployment_id`: exact release/policy/model and permitted role/account/store binding.

A signed-by-process compatibility receipt (not an invented human signature) records reviewer-approved code-only mappings. It permits consumption of compatible historical evidence, not broker authority. Changed features, target, holding/exit policy, selection regime, fee basis or risk semantics create a new contract/cohort and require a declared migration. Old experience remains queryable and may be explicitly excluded; never delete or silently reinterpret it. Model fitting never selects rows by code SHA alone.

## Data contracts

All records have `schema_version`, immutable `id`, `recorded_at_utc`, `release_id`, `evidence_lane` (`BROKER_PAPER`, `LOCAL_SIM_REAL_DATA`, `SYNTHETIC_TEST`), and source references. Decimal money/quantity are canonical strings; never binary float accounting. Market numeric features may be floats with explicit finite validation. Canonical digest and unique keys enforce identical replay and reject conflicting duplicates.

| Contract / proposed table | Required content / invariants |
|---|---|
| `Observation` / `core_observations` | symbol/asset/feed identity, raw-data digest, source start/end and receipt time, available-at evidence, feature names/values/version, symbol dependencies, calendar/time evidence, decision sequence. Every input was received before the decision; no partial future bar |
| `Decision` / `core_decisions` | observation ID, policy/model/activation IDs, acknowledged learning-receipt ID (including NO_CHANGE), mode COLLECT or PREDICT, expected outcome and cost basis, action, ordered gate results, chosen/rejected symbols, valid-until, snapshot/ownership version. Record refusals too; no retrospective model lookup |
| `EntryIntent` / existing `order_intents` plus `core_intent_links` | decision ID, account hash, symbol/side/quantity, deterministic client order ID, request digest, owner/fencing generation, claim state, protection-plan ID. One accepted claim per semantic intent; ambiguous sends are never reissued |
| `ProtectionPlan` / `core_protection_plans` | entry intent, owner, stop and deadline/close-buffer, clock contract, baseline inventory generation, allowed exit quantity rule. Durable before POST, acknowledged by healthy guardian; covers every incremental partial fill |
| `BrokerEvent` / existing fills/orders + `core_broker_event_sources` | provider event ID and raw digest, order/client ID, occurrence/receipt chronology, fill quantity/price, correction link, source endpoint/account/environment. Duplicate event is inert; conflicting payload is integrity failure |
| `CostItem` / `core_cost_items` | component, amount or null, currency, source `BROKER_REPORTED`, `CONTRACTUAL_ZERO`, `MODELED`, `UNKNOWN`; document/activity ID, effective dates, allocation rule, revision, supersedes. Explicit zero requires applicable proof |
| `ReconciliationProof` / `core_reconciliation_proofs` | acquisition attempt evidence, order/fill watermark, independently derived expected quantities/cash, actual observations, comparison result, unresolved items, certification generation. Raw observations never become a proof by repetition |
| `RoundTrip` / `core_round_trips` | owned entry/exit fill IDs, terminal-order evidence, protection receipt, reconciled flat **for this owned lot**, allocated costs, gross cash P&L, net broker P&L or null, modeled economics separately, outcome revision. Inherited holdings need not be zero |
| `LearningReceipt` / `core_learning_runs` | explicit input outcome revisions and exclusions, cutoff/availability, parent model, resulting model (parent for NO_CHANGE), target/feature/exit/selection contracts, training/validation split digest, permanent trial charge, algorithm/version, metrics, status/reason, proposed activation and actual activation reference/time (null if none) |
| `Activation` / `core_activations`, `core_active_model` | expected incumbent ID/generation, candidate hash, approved authority-envelope ID, validation ID, actor/reason, transaction/event sequence, effective time, rollback model. Compare-and-swap pointer, event and model digest are one transaction |
| `Health` / `core_health_events` | role + scope (account/symbol/lot/learning), state, first blocker and all objections, first/last seen, evidence IDs/age, last useful progress, next retry/expected event, recovery requirements |

Add these tables to the **authoritative operational store**, through one explicit additive migration. Do not let normal reads migrate. Keep old experiment/learner stores as read-only evidence sources once their writers are deliberately retired. During transition use a replay-safe importer with per-source cursors and digests; no cross-DB business transaction. Existing broker intent/fill IDs are preserved. There is no second new-core order outbox.

One SQL transaction writes decision + intent + protection handoff + reserved quantity. Network acquisition occurs outside the writer lock, then state versions and freshness are rechecked inside the short transaction. The broker side effect follows the durable claim. A crash may leave an uncertain intent, but cannot erase the evidence that an attempt may have occurred.

The final entry-authority check and transition to SUBMITTING share a writer transaction. Recovery may retire an expired claim only while durable state proves it never reached a possible-send state; the same state fence prevents a delayed original sender from posting afterward. Retain the original decision, intent and precise refusal evidence. A fresh observation may then claim a new slot. Broker 404, elapsed time or a generic error never supplies definitive-unsent proof.

Cash authority reflects current accepted evidence. Importing a cash-affecting revision invalidates any superseded certification in the same transaction; raw broker cash never repairs the gap by itself. Independently sourced complete cash activity can remain authoritative while fee allocation and outcome net are pending. Rejected batches roll back their business changes and retain the full rejected envelope, but quarantine follows the actual conflicting source/ownership graph rather than every unrelated item included in the batch.

## States and recovery

State is **per role and scope**, not a single Boolean for the entire installation.

| State | Example | Behavior / exit |
|---|---|---|
| `READY` | Fresh eligible observation, certified ownership, healthy guardian | Entry may proceed through final pre-send checks |
| `TEMPORARY_WAIT` | Market closed; one symbol stale; inadequate buying power; clock interval overlaps boundary | No new entry for affected scope; retry at next expected event. Guardian/outcomes/learning remain independent |
| `RETRYABLE_FAILURE` | Timeout, 429/5xx, incomplete pagination, changing non-atomic marks, DB busy | No assumption of success; bounded backoff 1/2/4/8/15 s with jitter, then capped 15 s. Provider retry-after can lengthen it. Escalate health after 5 min; duration alone does not turn uncertainty into a ledger contradiction |
| `MANUAL_PAUSE` | Explicit operator entry pause or preserved legacy manual stop | Durable until an explicit audited resume using fresh readiness. Never auto-clear |
| `INTEGRITY_FAILURE` | Conflicting client ID/payload, unowned quantity, fill revision conflict, cash discrepancy after complete valid acquisition, wrong account, corrupt store | Quarantine affected authority/evidence; account-wide execution only if ownership/account/store could be wrong. A deterministic preapproved repair may recover automatically after fresh proof and an audited resolution; unresolved ownership/corruption needs reviewed repair. Repeating broker observations does not repair it. Other trustworthy outcomes and learning continue |

For retryable acquisition failures, return to READY only after a **new bounded, complete reconciliation proof**, fresh timing/data required by that decision, no unknown exposure, valid guardian receipt, and no manual pause/unresolved integrity quarantine in scope. No operator reset is required. Historical clean results do not unlock entries. Recovery appends `Recovered(previous_event_id, new_proof_id)`; never overwrites failed evidence or clears unrelated stops. A closed-market wait can coexist with a manual pause or unresolved integrity failure; show all and retain the highest-authority refusal.

Malformed/untrusted provider data is quarantined and blocks affected entries. It is neither accepted nor automatically alleged to be a ledger contradiction. Persistent protocol failures require operator/engineering attention but remain separately classified. Actual valid observations proving a contradiction latch immediately. Quarantine removes no known owned protection authority; a genuinely ambiguous symbol/owner must not be sold blindly.

Intent states: `PREPARED -> CLAIMED -> ACKNOWLEDGED | SUBMISSION_UNKNOWN | DEFINITIVELY_REJECTED`; then order lifecycle `PARTIAL/FILLED/CANCEL_PENDING/CANCELED/EXPIRED`. After any possible send, recovery queries the **same client ID**, imports all fills, and reserves worst-case exposure until terminal proof. A 404 immediately after timeout is not proof of no order. No clock timeout creates permission to POST again. A canceled partial order still owns its filled quantity and needs protection. A restart never replays yesterday's fresh-entry decision.

## Protection and reconciliation

The guardian consumes fill-derived owned lots plus a certified baseline; it cannot grant ownership by writing an observation into the same table it trusts. Maintain raw snapshot and certified inventory generations separately. Every ownership allocation is attributable to an accepted intent; inherited inventory has a separate immutable owner until explicit handover. A mark's receipt time is not its provider as-of time: record both, and require genuine freshness evidence for a price-triggered stop. If price timing is unknown, retain the independent time-deadline exit path rather than fabricating a current mark.

New entry is blocked if its protection plan is not durable and the guardian is not healthy. Fill import immediately updates protected quantity. Stop-loss and deadline triggers compete for one unique exit intent; cancel/replace and partial exits retain the same quantity reservation. The maximum permissible sell is known owned open quantity minus already committed exit quantity. Never flatten unrelated inherited holdings or infer whole-account flatness from one lot.

Keep strict cash, quantity, identity and order/fill comparisons. Separate mark-to-market valuation uncertainty from cash-flow discrepancies. Multiple moving-mark snapshots may justify a wait, never certification. Bound acquisition, preserve raw samples, fetch paginated activity completely with overlap/deduplication, account for cancellations/corrections and only then certify the expected state. Retain provider-atomicity limitation explicitly.

During provider outage, local supervision can keep trying but cannot guarantee exchange execution. Broker-held protection should be used only where the exact instrument, fractional quantity and order type are verified supported; do not assume brackets protect the existing fractional lane. Preserve the independent deadline worker and current exits through transition, with explicit non-overlapping lot ownership. Manual entry pause does not stop owned risk-reducing exits.

## Timing contract: preserve ±2 seconds; change only through review

**`PAPER_TIME_V2` was approved for isolated implementation on October 14, 2026; exact operational commissioning remains subject to M6 review.** This retains the approved two-second relative-skew bound. It replaces PR288's exact Windows source/error/poll predicate as trading authority with decision-specific timing evidence. Existing runtimes retain their current contract/refusals until commissioned handover. No OS change is part of this design.

For a raw provider timestamp `p` acquired between local wall samples `w0,w1` and monotonic samples `m0,m1`, retain offset interval `[p-w1, p-w0]`. Require two advancing broker samples within a total acquisition budget of **5 s**, mutually consistent intervals wholly inside **[-2 s,+2 s]**, unchanged account/provider/session identity, and wall-versus-monotonic continuity. Keep the existing **50 ms** discontinuity boundary initially; any alternative is a separately versioned change. Timestamp resolution is recorded; this interval is relative-clock evidence, not a certificate of UTC accuracy.

Use monotonic elapsed time for transport timeouts, backoff, watchdogs, within-process evidence age, holding duration and expiry. Clock evidence lasts at most **120 s**, with the stricter bound of the consuming decision. Persist raw UTC audit fields and boot/process ID; monotonic values are never compared across restart. Restart invalidates cached proofs and reestablishes broker chronology before entries.

After awaited inventory acquisition, evaluate against a current validated projection of the original time proof. Persist that projection with the decision so claim validation is reproducible; never replace the original acquisition timestamps or refresh an old observation/mark. Compute conservative monotonic protection expiry from provider-domain bounds and a matching monotonic anchor, including when the session close buffer shortens the hold. Do not subtract local-wall audit time from a provider-domain deadline. The final send consumes the same expiry inside its transactional authority check.

For each consuming decision, derive conservative earliest/latest provider time from fresh proof:

- **Entry:** the entire interval must lie inside broker-confirmed exchange session, before `close - 120 s`, before the holding target, and inside the observation's ≤120 s freshness limit. If any interval crosses a boundary, wait. Five-minute bars must be closed and actually received. Future feature/price/label checks are not widened by two seconds. SPY is a real dependency of existing features; another roster symbol is not.
- **Owned exit:** monotonic holding deadline and known fill chronology are independent of entry-market research. Treat an uncertain interval overlapping a deadline as due at the earliest safe action, never as permission to extend the hold. After restart use fresh broker clock and durable fill/deadline metadata; if already due, attempt the risk-reducing exit through ownership/order gates. Unsupported/out-of-session broker execution remains visible and retried, never reported closed. Unknown ownership still forbids blind selling.
- **Outcome:** event order/ownership/terminal evidence and availability cutoff matter; a new market-clock sample or open session does not gate arithmetic over already durable evidence. Suspicious timestamps are quarantined per record. Fee corrections create revisions rather than backdating completion.
- **Learning:** immutable availability sequence and training cutoff enforce causality. A late outcome cannot appear in an earlier model. Label maturity is checked before data access. No dependency on a current entry clock while processing historical certified records.

**Where independent UTC accuracy is required:** correlating events from unrelated clock authorities, external publication/news times, cross-host leases, or externally timed datasets/holdouts where causal availability cannot be established from immutable receipt ordering and the approved provider domain. Require an independently bounded reference for those operations or keep them in WAIT/quarantine. The MVP excludes news/cross-host research. Broker timestamps plus the broker calendar are the declared time authority for the single-provider PAPER lane; shared provider error remains a documented limitation. OS wall UTC supports audit display and TLS but is not used for elapsed-duration decisions. Windows synchronization health remains a diagnostic; a matching server name or recent success is not proof of absolute error. This tradeoff must be explicitly reviewed, not disguised as a harmless refactor.

## Cost accounting

For a fully closed long lot, `gross_cash_pnl = sum(exit_qty*exit_price) - sum(entry_qty*entry_price)` after exact fill allocation. Include any attributable cash adjustments/corporate-action effects or mark unresolved. Fees can arrive after fills and must have their own IDs and allocation revisions. Never infer fee completeness from order terminality.

- `BROKER_REPORTED`: observed fee/activity amount including explicit zero, with evidence.
- `CONTRACTUAL_ZERO`: documented applicable provider/account/instrument/period contract states this component is zero; keep document hash/effective interval and reviewer record. No inference from marketing or a field being absent.
- `MODELED`: versioned assumption, reported only in modeled economics.
- `UNKNOWN`: null amount, explicit pending reason and retry path.

`broker_net_pnl` is populated only when required actual components are `BROKER_REPORTED` or applicable `CONTRACTUAL_ZERO`. Otherwise show gross P&L and `COSTS_PENDING`; never display a numeric “verified net.” For modeled economics, use actual known components plus estimates **only for missing components**. For a wholly simulated trade use simulated fills and a complete cost model, always SIM-labeled. A modeled substitute is not added to the actual value of the same component.

Fill-price returns already include paid spread and realized execution-price effects. Implementation shortfall versus the decision reference is a diagnostic, not another deduction from actual P&L. A separate incremental stress for unmodeled latency/impact is allowed only in the modeled field, explicitly identifying what is additional. Late costs update the current outcome revision exactly once and trigger learning reconsideration without adding another trade sample. Prior learning receipts remain immutable.

Alpaca describes PAPER as simulated execution and lists omissions such as market impact, latency slippage and queue position ([provider specification](https://docs.alpaca.markets/us/v1.4.2/docs/paper-trading)). Broker-PAPER fills prove broker integration, not live execution quality or real-world profitability. The audit did not establish a contractual zero for all fee components. The [supplemental provider-cost check](../../reviews/2026-10-13-paper-redesign/provider-paper-costs.md) records later documentation evidence and its applicability limits for M6.

## A real, bounded learning loop

Choose **one small regularized outcome predictor** for the new core. Reuse the existing standardized ridge implementation and ten causal features; retain alpha=1 and seed=0, with no feature/hyperparameter search. The new target is `owned-executed-net-return-v1`: realized return on entry notional for the exact fixed stop/deadline/selection contract. This is explicitly different from the old fixed-30-minute market-return target; never feed early stopped returns into a market-label model or mix the artifacts.

Train from certified, fee-complete owned round trips only. Untraded observations remain recorded but have no invented executed outcome. Results are conditional on the declared collection/entry policy; do not claim unbiased returns for unselected opportunities. Partition incompatible selection/exit contracts; previous market-label models remain diagnostic baselines, not initial coefficients disguised as experience. This sacrifices sample volume for a directly attributable trade-learning path. A separate all-opportunity fixed-horizon predictor is a later optional project, not an MVP dependency.

**Versioned learning envelope approved for isolated implementation on October 14, 2026; operational model use and unattended activation remain separately commissioned:**

- **October 14 user amendment: daily all-history learning, with recent emphasis.** Begin after ten completed trading sessions and consider learning after every completed exchange session, including quiet sessions. Train the resulting model on all eligible historical outcomes; there is no 60-session history cutoff. Raw episode weights are 2 for the latest ten completed exchange sessions at that fit's cutoff and 1 for earlier sessions, normalized to mean 1 within the fit. Use these weights consistently in preprocessing and ridge loss. This fixed 2× emphasis is an implementation choice, not a tuned parameter. A verified session calendar determines recency; ten sessions with trades is not a substitute for ten exchange sessions.
- A modern learning cutoff later than the authoritative execution clock produces a truthful NO_CHANGE before data materialization or a trial charge; it cannot move recency into future sessions. Preserve the requested cutoff and actual completion time. Repeated refusal is immutable, but reaching that cutoff permits a new valid consideration without overwriting the refusal.
- At most one candidate **procedure** per completed session, permanently charged before any fitting. All five validation-fold fits, validation, final refit and reproducibility work share one worker and the existing 30 s child budget. Insufficient or unchanged evidence yields NO_CHANGE; ten elapsed sessions alone does not replace the episode floors.
- Validate the fixed training procedure through five expanding chronological folds on the latest five eligible validation sessions. The first fold requires at least 30 certified training episodes across five earlier sessions; the validation set requires at least ten episodes across five later sessions. Each fold trains only on earlier revisions actually available at its own cutoff, with nonoverlapping feature/holding windows and at least 30 minutes embargo. Reconstruct immutable outcome revisions as of that cutoff; today's late correction cannot enter yesterday's fit. Record when validation targets became available for scoring. Canonical protected ranges are excluded before materialization, using execution time for reservation lifecycle. Development validation is consumed and cannot become a newly claimed untouched holdout.
- After the fixed validation gates pass, refit on all current eligible history, including the development-validation outcomes. Export final-refit inputs/weights/parameters separately from fold models and scores. The final artifact passed **procedure validation**; it has no independent held-out score after consuming all eligible history. Retain all old artifacts and version the new learning contract rather than relabeling old fixed-split receipts.
- If insufficient data/costs/compatible contracts: `NO_CHANGE` with parent=result, exact input/excluded IDs and reason. Every newly eligible revision is eventually included in a consideration receipt, even when no fit is allowed. Repeated identical input/cutoff/parent with the same admission facts is idempotent.
- Clip fitted predictions to ±100 bps, retain fixed risk/stop/horizon. Require finite coefficients, reproducibility, ≥5% validation MSE improvement versus both each fold's training-only constant baseline and the **historical incumbent policy** on identical validation episodes, and no worse error on the worst validation session. Historical comparisons use each episode's exact contemporaneous decision model/prediction, verified available before that decision; model IDs may differ across episodes. COLLECT is explicitly a zero comparison, not a fitted model. The −20 bps synthetic comparator remains explicitly fixture-only. Never score today's parent retrospectively on data it trained on; the current parent remains lineage/rollback identity. These are engineering candidate gates, not proof of profitable trading.
- Before first PAPER model use, record exact artifact approval and the fixed learning authority envelope. Subsequent unattended changes are allowed **only if that authority has explicitly been commissioned**; plan approval by itself does not supply it. Otherwise record `AWAITING_ACTIVATION` and continue using the incumbent. No automatic risk, horizon, universe, feature or algorithm changes.
- Apply a candidate at a decision boundary with no unresolved submission/claim. Existing open positions retain their entry model and protection plan. An atomic compare-and-swap writes activation event and active pointer; trader acknowledges the model digest in its next actual decision. Crash before commit leaves incumbent; crash after commit reloads candidate. Ambiguous/bad artifact fences entries; guardian/outcomes continue.

During cold start, keep the explicitly labeled, bounded COLLECT policy only if commissioned. Natural eligibility still applies; no quota, forced trades or relaxation to create labels. In PREDICT mode, entry needs positive conservative expected net return after a separately declared **incremental** 10 bps uncertainty/stress reserve (not a second realized slippage charge). This reserve is a proposed modeled default and does not alter actual P&L. If the model abstains persistently, report that honestly; do not auto-reenable collection or lower the reserve.

Learning receipt statuses: `NO_CHANGE`, `FIT_FAILED`, `CANDIDATE_REJECTED`, `AWAITING_ACTIVATION`, `ACTIVATED`. For every case record prior/resulting model, outcome revisions, validation or why none was run, trial charge if attempted, completed time and activation time or null. A later activation appends a completion receipt linked to the original learning run; it never edits an earlier AWAITING_ACTIVATION record. The joined evidence view supplies that activation time. A later decision must acknowledge the relevant learning receipt and exact active model, including a NO_CHANGE retaining the incumbent; merely writing a model file is insufficient.

**Required synthetic demonstration:** fixture-only completed trades under the same exit contract have balanced +20/−20 bps outcomes after explicitly known costs, with one causal feature identifying the sign. Their actual COLLECT decision models supply the explicit zero historical-policy comparison; the −20 bps fixture parent is a separate labeled benchmark and the incumbent for the later activation demonstration, never relabeled as those trades' historical model. Start with 30 training episodes across five sessions and 10 scored episodes across five later expanding folds. After procedure validation, refit all 40 eligible outcomes. Ridge learns nonzero coefficients and beats the training-only constant comparison; for a later positive-feature observation its final-refit prediction exceeds the 10 bps reserve, changing abstain to eligible buy. Use genuine production decision and activation code with a synthetic broker, and distinguish that fixture from real-data simulation and broker-PAPER. Prove daily consideration, unchanged/quiet-day NO_CHANGE, retention beyond 60 sessions, recent weighting, and causal late-revision handling separately. Preserve the earlier fixed-split evidence as historical. A companion insufficient-evidence fixture must retain the incumbent with `NO_CHANGE`.

Measure prequential prediction error, after-cost outcomes, coverage/abstention, activation counts and data exclusions by policy version and session. Pair incumbent/challenger predictions on later unseen opportunities without inventing counterfactual fills. Report sample size and session dependence; no inference of persistent improvement from MSE on seen validation or from a few trades. Preserve an untouched final holdout/evaluation budget in the canonical registry, used only in a separately registered evaluation. No promise of improvement every day.

## Deployment and operation

One versioned nonsecret configuration names PAPER endpoint/account hash, operational DB, input feed/roster/feature contract, exact policy/model/clock IDs, risk values, cadences and canonical holdout source. Secrets remain references to the existing protected environment file; never copied into config, logs, bundles or task arguments. Reject unknown keys, LIVE mode and endpoint/account mismatch. Keep existing stricter limits: one new position, 50 bps position value, 25 bps entry risk, 100 bps stop, 30-minute horizon, ≥120 s close buffer, 500 bps buying-power reserve; inherited exposure remains included. These settings do not guarantee broker acceptance.

Build a release manifest with code, `uv.lock`, interpreter, installed distribution hashes, schema and config. Prepare dependencies with `uv sync --frozen` in an isolated release directory, never in a running venv. No network install during startup. Use the existing native hidden job host, standard account, supported script policy and process-tree cleanup; no execution-policy bypass added by this plan. Role startup attests its actual manifest and store identity. Restart checks pending intents and certified ownership before entry readiness.

Dashboard first shows each role's last useful progress and a single causal first blocker with proof age, next action, and automatic/manual recovery class. Order entry refuses first on account/ownership/integrity/manual authority, then guardian/recovery/timing, then symbol data and strategy. Show the full objection list beneath it. A normal closed-session wait must not hide stale protection, unknown submissions, an unprocessed completed lot, or a missing activated model.

## Migration and rollback principles

1. Preserve online SQLite backups with integrity check and restore test, plus nonsecret task XML/config/release hashes and canonical holdout/trial snapshots. Do not copy only a WAL database's main file while it is active.
2. Build the new core off-line against synthetic data and read-only imported evidence. Historical source events retain original identities, classifications and cost uncertainty. No current broker writer changes yet.
3. Add schema only through the explicit migration after compatible readers and a rollback version are prepared. Old DBs remain archives; import is restartable/deduplicated. Do not renumber existing fills/intents or reset stop history.
4. Handover fences old entries, proves no competing writer, reconciles pending orders/positions, then assigns entry generation to the new core. Never disable old protection until each assigned lot is acknowledged by tested new protection; retain legacy owner for inherited lots until separately proven transferable.
5. Rollback fences new entries, resolves uncertain sends by same ID, preserves new evidence, and selects the compatible prior release/model pointer. **Never restore an old trading database over newer broker activity.** If the old release cannot read new schema or ownership, remain in protection/recovery-only mode and repair forward.
