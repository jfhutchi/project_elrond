Market session

What the market-hours loop has been doing. Every fifteen minutes while a session is open, Elrond checks reconciliation, the kill switch and market-data freshness, and writes down what it found — including when it found nothing wrong.

This page is about liveness, not about edge. A loop that observed twenty-six times today has not discovered anything; it has confirmed that the parts of the system which can go wrong between one close and the next have not.

What this loop deliberately does not do
It cannot place an order. The observation pass is built without a submitter and without a strategy runner — not a setting that disables them, but no connection to them at all, so there is no route from watching a session to trading in one.
It does not evaluate the strategy. The deployed strategy was qualified on daily bars evaluated after the close; running it every fifteen minutes would be a different strategy carrying forward evidence it never earned. The trading cycle still runs once, after the close.
Not built yet, and not shown as empty
The target operating model asks for an event stream, a worker queue with priorities and backpressure, per-worker budgets, and escalation state. None of that exists, so none of it appears above as a panel reading zero.
An empty widget looks like a system that has nothing to report. The honest version says the measurement does not exist. Concretely: no experiment has ever run, no research worker has ever been dispatched, and no statistical budget has ever been spent — so a queue depth or a budget gauge would be reporting zero for a mechanism that was never wired, which reads as health.
Intraday event detection additionally needs intraday data. The configured feed supplies one bar per day, so there is nothing for an event stream to watch between one close and the next.
